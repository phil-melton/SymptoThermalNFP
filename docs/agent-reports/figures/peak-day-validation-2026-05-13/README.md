# Peak-Day Validation Figure Generation

These figures were generated by the deterministic validation harness in
`scripts/validate_peak_day_accuracy.py`. They are plain SVG files produced with
Python standard-library string rendering, so they do not depend on matplotlib,
numpy, pandas, or a browser runtime.

## Regenerate

Run from the repository root:

```powershell
.\.venv\Scripts\python.exe scripts\validate_peak_day_accuracy.py
```

Default outputs:

- Report: `docs/agent-reports/peak-day-validation-2026-05-13.md`
- Results JSON: `docs/agent-reports/peak-day-validation-2026-05-13-results.json`
- Figures: `docs/agent-reports/figures/peak-day-validation-2026-05-13/`

## Figure Files

- `temperature-history.svg`: representative cycle BBT line, coverline,
  expected Peak Day, detected Peak Day, and temperature confirmation marker.
- `symptom-history.svg`: representative mucus/symptom score timeline with
  bleeding markers and Peak Day labels.
- `curveball-panels.svg`: compact panels for the exception cases, including
  false peaks, late ovulation, slow rise, disturbed/missing temps, no mucus,
  premature rise, bleeding, and open-ended peak-quality mucus.
- `accuracy-summary.svg`: summary bars for exact Peak Day accuracy, +/-1 day,
  +/-4 day, and no-false-peak performance.

## Data and Design Inputs

The script builds known-ground-truth synthetic `DailyObservation` cycles, then
runs `evaluate_observations` from the domain rule engine. The generated
population uses:

- `STATISTICAL_SEED = 20260513`
- `STATISTICAL_CYCLE_COUNT = 160`
- 11 hand-authored curve-ball and exception charts
- source-shaped cycle length and Peak Day distributions cited in the report
- physiologic BBT ranges and rise sizes cited in the report

The SVG renderers live in these functions:

- `render_temperature_history`
- `render_symptom_history`
- `render_curveball_panels`
- `render_accuracy_summary`

The raw case-by-case validation results are preserved in
`docs/agent-reports/peak-day-validation-2026-05-13-results.json`.

## Reuse Notes

For a future browser app, these SVGs can be used as static reference assets, or
the rendering logic can be ported to HTML/SVG components. Keep the same visual
semantics when reusing them:

- Purple dashed vertical line: expected Peak Day.
- Orange dashed vertical line: detected Peak Day.
- Gold dashed horizontal line: BBT coverline.
- Blue dashed vertical line: temperature confirmation.
- Orange temperature points: disturbed readings excluded from confirmation.
- Red dots below symptom axis: medium/heavy bleeding.

If the rule engine changes, regenerate the report and figures with the same
script so the visuals and metrics stay synchronized.
